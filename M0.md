# M0 — Walking Skeleton

**Gate:** An event published in a test travels through the bus to a fake display, which asserts a frame. `pytest` green on a laptop. `import-linter` fails a deliberate violation.

**Effort:** 8 IED · **Confidence:** H · **Hardware required: none**

**Why this first:** M0 is the only milestone whose output is entirely infrastructure, and it's the reason every later milestone is testable. It is also the 8 IED you can do on a laptop while the board is out of stock in Beirut.

---

## A note on format

These aren't written as "As a user, I want…". For infrastructure work that framing produces noise — *"as a developer I want a repo so that I can write code"* tells you nothing. What PMP §10.1's Definition of Ready actually asks for is an **outcome stated as observable behaviour**, and that's the format used below. The user story returns at M3, where there's a user to have one.

Every issue below satisfies DoR. Copy each into a GitHub issue using the Task template.

## Epic 1.3 — Domain layer

### AVID-6 · The Event envelope
**Size:** S (0.5) · **Component:** domain · **SDS:** §9.1.1
**Depends on:** AVID-1

**Outcome:** Every event in the system's life carries what's needed to trace it and to measure it, and cannot be mutated in flight.

- [ ] Frozen, slotted, kw-only dataclass base
- [ ] Carries `event_id`, `correlation_id`, `timestamp_ms`, **`monotonic_ns`**, `source`
- [ ] Attempting to mutate an event raises
- [ ] Naming validator enforces `<domain>.<past_tense_verb>` (P4)
- [ ] `avid/domain/` imports nothing from `avid` and nothing third-party but `pydantic`

> **`monotonic_ns` is not redundant with `timestamp_ms`.** Wall-clock jumps — NTP steps, and the Pi corrects its clock seconds after boot. G1's P50/P95 histogram subtracts two event times; do that with wall-clock and one NTP step yields a *negative latency* that silently poisons the metric the whole project is graded on. Wall for humans, monotonic for arithmetic. Never subtract `timestamp_ms`.
>
> Frozen isn't stylistic either: handlers dispatch **concurrently** (§3.5.2), so a mutable event is a data race with extra steps.

### AVID-7 · RobotState and the transition table
**Size:** M (1) · **Component:** domain · **SDS:** §3.10
**Depends on:** AVID-6

**Outcome:** Every legal state change is declared in one table, and every illegal one is impossible to reach by accident.

- [ ] `RobotState` enum: BOOTING, IDLE, LISTENING, THINKING, SPEAKING, SLEEPING, DEGRADED
- [ ] Transition table implemented as a frozen mapping, matching §3.10.3 **exactly**
- [ ] `next_state()` is a **pure function** — no I/O, no clock, no globals
- [ ] Parametrised test over every documented transition
- [ ] `test_no_undocumented_transitions` — exhaustive over `product(RobotState, EVENT_TYPES)`; anything not in the table raises `IllegalTransition`
- [ ] Whole test module runs in <100ms

> SDS §3.4.2 claims *"ninety percent of the bugs in a system like this are illegal state transitions."* The exhaustive test is what cashes that claim, and it costs 4ms.
>
> Note the barge-in row (`SPEAKING + speech_started → LISTENING`). It's the one that'll bite in M5, and it's the transition that separates a companion from a kiosk.

### AVID-8 · Affect
**Size:** XS (0.25) · **Component:** domain · **SDS:** §3.10.1, §6.8
**Depends on:** AVID-6

**Outcome:** Emotional state exists as a concept entirely separate from operational state.

- [ ] `Affect` enum: IDLE, LISTENING, THINKING, HAPPY, SAD, CONFUSED, SLEEPING
- [ ] `affect.changed` carries `tier: 1 | 2` (§6.8's two-speed model)
- [ ] Nothing in `domain/` couples `Affect` to `RobotState`

> They're **orthogonal**. The robot can be SLEEPING-and-content or LISTENING-and-confused. Conflating them is the most common design error in this class of project and it produces a combinatorial mess you can't refactor out of later.

## Epic 1.4 — The event bus

### AVID-9 · EventBus core
**Size:** L (2) · **Component:** core · **SDS:** §3.5.1–§3.5.3, §9.1
**Depends on:** AVID-6

**Outcome:** A publisher can announce something happened without knowing, or caring, who reacts.

- [ ] `publish()` returns once queued — **not** once handled
- [ ] `subscribe()` requires a `name=` (§9.1.5 walks it; anonymous lambdas are invisible to the generator)
- [ ] Handlers dispatch **concurrently**, not sequentially
- [ ] Subscription is **static** — registered at composition time only; runtime subscription raises
- [ ] `correlation_id` propagates from a turn's origin event to everything downstream
- [ ] Test: two subscribers to one event both run, and in parallel

> Static subscription looks like a restriction and is actually the enabling constraint. §3.5.1 admits the bus costs you control-flow legibility; §9.1.5's drift check is the mitigation; and the check only works if the graph is knowable at import time. The restriction and the check are one design.

---

### AVID-10 · Failure isolation and backpressure
**Size:** M (1) · **Component:** core · **SDS:** §3.5.2, §3.5.5
**Depends on:** AVID-9

**Outcome:** A broken subscriber degrades one feature instead of killing the robot.

- [ ] A handler that raises is logged, swallowed, and republished as `system.handler_failed`
- [ ] **Test: a raising subscriber does not kill the publisher, and other subscribers still run**
- [ ] Per-subscriber bounded queue, default 100
- [ ] Overflow policies `DROP_OLDEST` / `DROP_NEWEST` implemented; **`BLOCK` raises at registration**
- [ ] Overflow publishes `system.handler_failed` with `reason="queue_overflow"` and increments a counter
- [ ] Guard: a handler *of* `system.handler_failed` that raises does not loop infinitely

> The isolation test is **the single most important reliability property in the system** (§3.5.2). A crashing display renderer must not kill a conversation. Write that test before anything depends on the bus.
>
> `BLOCK` is forbidden rather than discouraged — it would propagate backpressure into the audio path, which is the one place §2.8.1 has no slack.
>
> Silent drops are a debugging catastrophe. Loud drops are a tuning signal. That's why overflow is an event.

## Epic 1.5 — Ports and fakes

### AVID-11 · Port definitions
**Size:** S (0.5) · **Component:** core · **SDS:** §3.9.1, §9.3
**Depends on:** AVID-1

**Outcome:** The application declares what it needs from the physical world, in terms of what it needs — never in terms of what a device happens to offer.

- [ ] Protocols: `Camera`, `Servo`, `Display`, `Microphone`, `Speaker`, `Clock`, `EventBus`
- [ ] All `runtime_checkable`
- [ ] `Servo.move_to` documents that clamping is the **adapter's** job
- [ ] `Camera.capabilities` / `Servo.axes` exist (§3.9.3 negotiation — this is what keeps ADR-009 open without blocking anything)
- [ ] `Display.render` takes a **frame**, not a screen

> `Display.render(frame)` is doing more work than it looks. It's why the ILI9341 adapter can render offscreen and push RGB565 over `spidev` rather than fighting SDL2 for a framebuffer that no longer exists. **The port never promised a screen — only a frame.**

### AVID-13 · FakeDisplay
**Size:** S (0.5) · **Component:** adapters · **SDS:** §3.9.2, §14.8

**Outcome:** You can see what the robot's face did in a test run, without a robot or a face.

- [ ] CI uploads the frames as an artifact
